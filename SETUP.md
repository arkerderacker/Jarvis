# JARVIS — Groq Gesture HUD (updated from the supplied JARVIS-final-school-voice(1).zip)

This build starts from the supplied `app.py` and keeps the existing interface/features. The changes are limited to the requested fixes/upgrades:

- No API key is embedded in the HTML.
- Groq setup remains the first-run screen.
- Browser speech recognition is kept, with Groq Whisper transcription fallback.
- Browser text-to-speech is kept, with optional ElevenLabs voice support.
- The central JARVIS circle is fixed at the screen center and remains screen-facing.
- The center reacts to JARVIS voice activity.
- Existing revolving words and fireworks are kept.
- Camera/photo analysis uses the configured Groq vision model.
- Developer panel/code generation/live preview/download/ZIP remain.
- Settings now contain optional Home Assistant/Roborock bridge fields for later.
- Home Assistant credentials are stored server-side in `~/.jarvis/config.json`.

## 1. Run in Google Cloud Shell

Official Cloud Shell:
https://shell.cloud.google.com/

Upload this ZIP into Cloud Shell.

Then:

```bash
unzip JARVIS-Qrevo-Groq-final.zip
cd JARVIS-Qrevo-Groq-final

python3 -m venv .venv
source .venv/bin/activate

pip install -r requirements.txt

python3 app.py
```

When Flask prints that it is listening on port 8080, use:

Cloud Shell -> Web Preview -> Preview on port 8080.

Google's Web Preview supports apps listening on ports 2000-65000 and exposes the preview through HTTPS.

## 2. Get the Groq API key

Official Groq API keys:
https://console.groq.com/keys

Create a key.

Do NOT paste the key into the source code.

When JARVIS opens its setup screen, paste the key into the password box and press:

Initialize Jarvis

Leave "Save key to this device" checked if you want this Cloud Shell machine to remember the key.

The saved key is stored in:

```text
~/.jarvis/config.json
```

It is not stored in `index.html` because the UI is generated by `app.py`.

## 3. Test the voice

Press the microphone button.

On browsers that support SpeechRecognition, the browser transcribes speech.

If browser speech recognition is unavailable, JARVIS records microphone audio and sends it to the server's `/api/transcribe` endpoint, which uses Groq Whisper.

You should see your words appear in the chat input and then be sent automatically.

The browser must allow microphone access.

## 4. Test JARVIS speaking

Send:

```text
Hello Jarvis
```

JARVIS replies using browser text-to-speech.

While speaking, the center JARVIS core expands and pulses with voice activity.

If you configure an ElevenLabs voice in Settings, the ElevenLabs audio is analyzed with Web Audio when possible, so the core can react to the actual playback level.

## 5. Test camera/photo vision

Open:

Settings -> Camera

or use the camera/photo control in the chat.

Allow camera permission.

Press Start camera.

Press Analyze frame.

Ask something such as:

```text
What is in this image?
```

The frame is sent to `/api/photo`.

The Groq vision model is configured in `GROQ_VISION_MODEL` in `app.py`.

## 6. Developer button

Open:

Settings -> Developer

Enter a request such as:

```text
Create a responsive HTML calculator.
```

Choose HTML.

Press Generate.

You can then:

- Copy
- Save file
- Download
- ZIP
- Run/live-preview HTML, CSS, or JavaScript

The generated files are kept in:

```text
~/.jarvis/workspace/
```

## 7. Deploy JARVIS to a public website

For an easy free test deployment, use Render:

https://render.com/

You need a GitHub repository containing:

```text
app.py
requirements.txt
Procfile
.python-version
```

Create a new Render Web Service.

Use:

Build Command:
```text
pip install -r requirements.txt
```

Start Command:
```text
gunicorn --bind 0.0.0.0:$PORT app:app
```

Choose the Free instance.

Render will give you an `onrender.com` HTTPS address.

IMPORTANT:
Render free web services spin down after 15 minutes without inbound traffic and can take about a minute to wake up. Their local filesystem is also ephemeral. This means this is suitable for testing/hobby use, but do not treat `~/.jarvis/` as permanent cloud storage.

For production, move chat/photos/settings/task storage to a real database/object store.

## 8. Roborock setup later

The Settings panel now contains:

- Home Assistant URL
- Home Assistant long-lived access token
- Roborock entity ID
- Save bridge
- Test

Nothing controls the Roborock until you configure these fields.

Recommended bridge:

```text
JARVIS -> Home Assistant -> Roborock Qrevo S Pro
```

Home Assistant's official Roborock integration:
https://www.home-assistant.io/integrations/roborock/

Home Assistant supports Roborock vacuums paired with the official Roborock app, including the Qrevo series, and exposes vacuum controls depending on the device.

You will need an always-on Home Assistant host for reliable smart-home control. A phone is not a suitable always-on Home Assistant server.

Do not put your Roborock credentials or Home Assistant token in the frontend source code.

## 9. Important privacy/security note

The browser needs the Groq API only through the JARVIS server. The source does not contain an embedded Groq key.

However, if you deploy this Flask app publicly, protect the service before using sensitive data. The current app is a personal prototype and has developer command execution endpoints. Do not expose the Developer "Run" function to an untrusted public audience without adding authentication/sandboxing.
